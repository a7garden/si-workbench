# vault-tidy — 볼트 재구성/다듬기

기존 문서 전체를 훑어 si-workbench 표준 구조(`일지/`, `사업/<사업명>/`, `개념/`, `첨부/`)로 재구성한다.
첫 실행은 전체 패스, 이후 실행은 git diff 기반 증분 패스. 재실행 멱등을 지향한다.

## 안전 규칙 (최우선)

- git은 **로컬 버저닝 전용**. remote 추가·push·원격 동기화는 절대 하지 않는다.
- 첫 재구성 전 반드시 현재 상태를 git 커밋으로 박제한다(원본 보존 — 모든 변경은 히스토리에서 복구 가능해야 한다).
- **삭제와 병합은 계획 승인 후에만** 실행한다. 승인 없는 파괴적 변경 금지.
- frontmatter는 템플릿 스키마만 사용한다. 임의 필드 금지. 키는 영어, 값은 한국어.
- 위키 규범은 si-workbench:wiki를 준수한다.
- vault 경로 결정: `${user_config.vault_path}` → `%USERPROFILE%\.claude\si-workbench\config.json`의 `vaultPath` → 사용자에게 절대경로 문의. 순서대로 시도한다.

## 0. git 기반 마련

1. `<vault>/.git`이 없으면 `git init`한다. repo 로컬 범위로 `user.name`/`user.email`이 비어 있으면 `si-workbench` / `si-workbench@local`로 설정한다.
2. 전체를 스테이징해 초기 커밋: `vault-tidy: 원본 백업 (마이그레이션 전 상태)`.
3. `.gitignore` 작성(없으면): `.obsidian/workspace.json`, `.obsidian/workspace-mobile.json`, `.trash/`
4. 이미 git이 있으면: 미커밋 변경 목록을 보고하고, 사용자 동의를 얻어 커밋하거나 그대로 둔다(어느 쪽도 자동으로 덮지 않는다).

## 1. 스캔 범위 결정

- HEAD가 있고 `$ARGUMENTS`에 `full`이 없으면(증분): `git diff --name-status HEAD`의 변경 파일 + untracked만 대상. 대상이 없으면 "마지막 정리 이후 변경 없음"을 보고하고 종료한다.
- 첫 실행이거나 `full`이면: vault 전체 `*.md`(제외: `.obsidian/`, `.git/`, `.trash/`, `템플릿/`).

## 2. 분류·진단

노트마다 기록: 현재 경로, 추정 유형, 상태 태그.

- 추정 유형: 일지(파일명/H1이 날짜), 사업·연구(사업명 추정 가능), 개념(용어 정의 형태), 기타(미분류)
- 상태 태그:
  - `빈 노트` — 제목만 있거나 본문이 실효성 없음(1-2줄)
  - `부실 노트` — 있으나 최소 설명이 없음(대략 5줄 미만)
  - `파편 후보` — 같은 주제의 짧은 노트가 2개 이상
  - `스키마 누락` — frontmatter 없음 또는 키 불일치
  - `위치 불량` — 표준 폴더 밖
- 노트 본문은 스캔을 위해 읽되, 대용량 노트는 앞부분 요약만으로 판단한다.

## 3. 계획 수립 → 승인 (하드 게이트)

아래 표를 사용자에게 제시하고 **승인을 받기 전까지 어떤 쓰기도 하지 않는다**:

| 조치 | 대상 | 내용 |
|---|---|---|
| 이동 | 원래 경로 → 새 경로 | 표준 폴더 배치 + frontmatter 작성 |
| 병합 | 파편 목록 → 남을 노트 | 본문 통합. 사라지는 이름은 남을 노트 `aliases`에 등록(기존 `[[옛이름]]` 링크가 alias로 해석됨) |
| 보강 | 부실 노트 | 관련 소스(제안서·코드·기존 노트·세션 기록)가 있을 때만 무엇으로 채울지 제안. **추측 서술 금지** |
| 삭제 | 빈 노트 | 사용자 승인 필수 (git 이력에 남음) |

애매한 판단(사업명 귀속, 병합 대상 선정, 유형)은 이 단계에서 질문으로 해소한다.

## 4. 실행

- **이동**: 폴더 배치 + frontmatter 채우기(스키마 순서 고정) + H1 정리. 상대경로 링크·임베드(`![[...]]` 제외한 상대 경로)가 깨지지 않는지 확인한다.
- **병합**: 남을 노트에 본문을 통합하고 `aliases`에 사라지는 이름들을 추가한다. 중복 문장은 제거한다.
- **보강**: 승인된 항목만, 근거 소스를 `sources`에 남기며 채운다.
- **삭제**: 승인된 항목만.
- **위키링크 정비**: 새로 등장한 개념은 규범대로 노트를 만들고, 관련 사업 허브의 `## 문서`·`## 주요 개념` MOC를 갱신한다.

## 5. 검증·마무리

1. 죽은 링크 스캔: 전체 md에서 `[[...]]`를 추출해 대상 노트(또는 alias) 존재를 확인하고, 발견분을 수정한다.
2. 커밋: `git add -A` → `vault-tidy: 이동 N·병합 M·보강 K·삭제 D·링크수정 L` 형식.
3. 보고: 조치별 건수와 목록, 죽은 링크 처리 결과, 다음 실행은 증분으로만 동작함을 안내한다.
