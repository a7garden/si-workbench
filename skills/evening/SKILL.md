# evening — 퇴근 정산

무인 실행 스킬이다. daily-log와 daily-report의 절차를 조합해 한 번에 처리한다. 퇴근 루틴은 이 스킬 하나로 끝난다.

## 무인 실행 계약

[UNATTENDED] 사용자는 자리를 비운 상태에서 이 스킬을 실행한다. 어떤 단계에서도 사용자에게 질문하거나 응답을 기다리지 않는다. 모든 판단과 근거는 마지막 보고에 적는다. 사용자 확인이 필요한 사항은 실행을 멈추지 말고 보고서에 "확인 필요"로 표시한다.

## 공통 원칙

- 코드베이스는 읽기 전용으로만 다룬다. 어떤 저장소의 파일도 수정/삭제하지 않는다.
- 원격 저장소 변경 주의: `git push`, `svn commit`/`svn ci`, `git svn dcommit`, `hg push`는 불필요하면 실행하지 않는다. 로컬 `git commit`은 자유이며, 훅(block-push.ps1)이 원격 변경은 실행 전 사용자 확인을 요구한다.
- 위키 규범은 si-workbench:wiki를 준수한다. 업무기록 본문에서 개념이 처음 등장하면 `[[개념명]]`으로 링크하고, 개념 노트가 없으면 템플릿(`템플릿/개념.md`) 내용으로 생성한다. 죽은 링크 금지.
- 프로퍼티 키는 영어, 값은 한국어. 스킬이 임의 필드를 만들지 않는다.
- vault 경로 결정: `${user_config.vault_path}` → `%USERPROFILE%\.claude\si-workbench\config.json`의 `vaultPath` → 사용자 문의. 무인 실행이므로 어디서도 경로를 못 찾으면 질문하지 말고 실패 사유를 보고하고 종료한다.

## 절차

1. **오늘 일지 노트 확보** — `${vault}/일지/YYYY-MM-DD.md`(로컬 날짜). 노트가 없으면 템플릿(`템플릿/일지.md`) 내용으로 생성한다.
2. **저널 분석** — daily-log의 분석 절차를 그대로 수행한다: 오늘 저널(`%USERPROFILE%\.claude\si-workbench\journal\<오늘>.jsonl`) 로드 → session_id dedup → [SAMPLING] → cwd 기준 프로젝트별·시간순 재구성. `$ARGUMENTS`(세션에 남지 않은 구두 업무)가 있으면 분석 결과에 반영한다. 저널이 없고 `$ARGUMENTS`도 없으면 기록 근거 없음을 보고에 적고 3단계로 간다.

[SAMPLING] transcript JSONL 샘플링 규칙: (1) 전체 통독 금지. (2) 먼저 라인 수 파악. (3) `"type":"summary"` 라인과 user 발화(`message.role == "user"`이고 content가 문자열이거나 content[].type=="text")를 추출. (4) 마지막 assistant 텍스트 1-2개만 추가. (5) tool_result 본문은 읽지 않는다. 파일이 크면 앞부분 user 발화와 뒷부분 마무리를 우선.

3. **체크 확정 (증거 기반)** — `## 오늘 할 일`의 각 항목을 2단계 분석 결과와 대조한다. 완료의 명백한 근거가 있으면 `- [x]`로 바꾸고 근거(세션/프로젝트)를 보고에 적는다. 사용자가 이미 [x]한 항목은 유지한다. 근거가 없으면 [ ]를 유지하고 보고에 "증거 없음"으로 표시한다. 이 단계는 evening이 수행한다 — `## 업무기록` 외 섹션 무수정 원칙의 유일한 예외이며, 그 대상도 `## 오늘 할 일`의 체크 상태뿐이다.
4. **업무기록 기입** — daily-log와 동일한 계약으로 `## 업무기록`을 갱신한다:

[SECTION] `## 업무기록` 헤딩 아래부터 다음 `## ` 헤딩 또는 EOF 직전까지가 교체 범위(헤딩 자체는 유지). 헤딩이 없으면 문서 끝에 추가. 재실행 시 기존 자동 생성 내용이 통째로 갱신(멱등). 기록 규칙: 시간순 프로젝트/작업 블록, 각 항목에 무엇을·왜·결과, 한국어 완결 문장, 개념 첫 등장 시 `[[개념명]]` 위키링크(노트 없으면 템플릿 생성).

5. **보고서 출력** — daily-report의 [REPORT-FORMAT]을 그대로 따른다: 단일 코드블록, `[분류]` + `- 항목`, 분류 사이 빈 줄, 날짜/인사/장식 없음. AI가 그날 분류를 추론한다. 출력 직전 4점 자가점검: 코드블록 1개인가, `[분류]` 형식인가, 빈 줄 구분인가, 장식 없는가.
6. **내일 할 일 정리** — 3단계 후에도 `- [ ]`인 항목을 `## 내일 할 일`에 이어 적는다. 기존 항목은 삭제하지 않고, 완전히 동일한 문구는 중복 추가하지 않는다. `## 내일 할 일`이 초기 상태(주석과 빈 `- [ ]`)면 미체크 항목으로 채운다.
7. **종합 보고** — 아래 순서로 마무리한다:

```
실행 요약:
- 저널 N세션(M프로젝트) 분석, 업무기록 교체, 보고서 출력

체크 확정:
- [x] 항목 — 근거
- [ ] 항목 — 증거 없음 (직접 확인 필요)

내일 이월:
- (6단계에서 옮긴 항목)
```

## 금지

- `## 오늘 할 일`에서 근거 없이 항목을 [x]로 바꾸지 않는다.
- `## 비고`는 건드리지 않는다.
- 보고서 코드블록 외의 장식(인사, 이모지, 요약 박스)을 추가하지 않는다.
